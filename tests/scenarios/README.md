# Сценарии ручных тестов

Каждый файл `<имя>.md` — один сценарий: предусловия, шаги с результатом на экране
(`видно:`) и ожидаемые строки лога/трассы (`## expect sd`, `## expect sa`).
Сценарий выполняет человек. Скрипт только сверяет трассировку с ожиданием.

## Сценарии

- `chat_sd_sa` — переписка SD ↔ SA (обе стороны проверяются по логам).
- `chat_sd_sim` — переписка SD ↔ SIM (SIM не логирует: только действия и SD).
- `chat_sa_sim` — переписка SA ↔ SIM (SIM не логирует: только действия и SA).

Каждый сценарий — шесть контрольных точек в фиксированном порядке. Имена профилей
и тексты сообщений в проверки не входят.

## Порядок прогона

```
./tests/scenarios/run.sh start chat_sd_sim   # метка START в лог SD
# выполнить шаги из chat_sd_sim.md
./tests/scenarios/run.sh end                 # метка END
./tests/scenarios/run.sh compare             # сверка
```

- Имя сценария скрипт берёт из метки START в логе SD. Отдельно указывать его при
  `compare` не нужно.
- SD читается из `~/.local/share/com.magnus.stauri-app/logs/stauri.*.log`.
- SA читается из трассы телефона (`adb shell run-as com.magnus.stauri_app cat bridge-trace.log`)
  по окну времени между метками.
- Код выхода `0` — все ожидания выполнены; `1` — расхождения.

## Что такое ожидание

- Строка `- текст` — должна встретиться в логе стороны, после предыдущего ожидания.
- `- not: текст` — не должна встретиться в окне.
- `А | Б` — достаточно одного из вариантов (сигнал или опрос).
- `{ПЕРЕМЕННАЯ}` — подставляется из раздела `vars:`.

## Ограничения

- Проверяется лог, а не то, что на экране. Экран описан в шагах и проверяется глазами.
- Шаги SIM не логируются приложением: SIM проверяется только по её влиянию на SD/SA.
- Телефон: сигналов нет, поэтому SA обновляет данные опросом раз в 10 с.
- Метки в лог SD пишет скрипт. Если лог не открыт для записи, метка не появится.
