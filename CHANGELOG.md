# Changelog

All notable changes to Stauri. Sections are generated by
`scripts/release-changelog.sh` from Conventional Commits; new versions go on top.

## [0.5.3] — 2026-11-24

### Added
- A domain switch in the profile ENS block: `.stateofus.eth` (the default) and
  `.eth`. A regular `.eth` name owned by one of the profile's wallets can be
  attached to the profile — the registry owner and the address record are
  checked, and attaching costs nothing. Registering `.eth` names inside Stauri
  is not available yet; the screen says so instead of failing after the password.
- Invites and names typed into "join by invite" are recognised as ENS names:
  `name.eth`, `name.stateofus.eth` and a bare label are sent as a contact
  request to the chat key recorded on the name.
- Registration now writes the profile's chat key into the resolver record.
  Earlier builds wrote the paying wallet's key, so a contact request to such a
  name went to a key nobody holds. A repair command (`update_ens_public_key`)
  rewrites the record of a name registered by an older build.
- `docs/en/ens_eth.md`: what registering, renewing and managing `.eth` names
  inside Stauri needs, in stages. Linked from the TODO in all four About pages.
- `scripts/clean-disk.sh`: a dry-run-first cleanup of build artefacts inside the
  repository; it never touches `binaries/`, the keystores or the user's data.

### Changed
- The ENS block is cleared when the profile editor opens: a price, a "taken"
  answer or a "Name registered" banner from a previous visit no longer stays on
  screen.
- Icon rail order: Home, Profile, Chat, Wallet, dApps, Market.
- The "Edit profile" link is gone from the left profile pane — the pencil in the
  header and the Profile tab already open the editor.
- The CHANGELOG is in English, starting from this release.

### Fixed
- Android: `libstatus.so` and `libsds.so` are packaged from
  `src-tauri/binaries/android/<abi>/` and synced into the generated project, so
  a build no longer starts with "the backend is not running"; the manifest no
  longer carries a broken `networkSecurityConfig` attribute.
- Profile creation on Android: when the login signal carries no key uid, it is
  read from settings instead of leaving a profile nobody can open, and a backend
  that is not running is reported as such instead of "the backend created no
  profile".
- RPC failures show the real message instead of `[object Object]`.
- A back arrow on the new-profile PIN screen returns to the previous step.
- The suggested route is logged when a transfer or a registration is refused —
  addresses, calldata and fees, no secrets — so a refusal can be told apart from
  a route built for the wrong sender.

## [0.5.2] — 2026-11-23

### Added
- Attaching the ENS name owned by the profile wallet: after restoring from a
  phrase the name is not lost — the ENS screen recognises it as this profile's
  and offers "Attach to this profile" with no transaction and no deposit.
- A "Stauri v. <version>" line on the profile: the build version, plainly
  visible, and a re-check for updates on click — the background check runs once
  an hour.

### Fixed
- One way to sign in on both platforms: what you type is the PIN (digits on the
  phone, a password on the desktop), and the envelope is created silently after
  login. The screen no longer asks to "create a PIN" after the "password" — the
  same thing, twice.
- A successful restore from the phrase opens the profile and leaves the recovery
  screen: before, the session opened on the backend while the interface stayed on
  the password field.
- A node crash after login (`node.crashed`) turns into a message instead of an
  endless hang while the messenger starts; "seed phrase not saved" no longer stays
  red after a successful restore.
- A wrong password on the recovery screen no longer leaves you on the same field:
  the screen moves itself to choosing "new local copy", where the "Existing
  profile / New local copy" tabs live, together with the rule: an old password is
  not checked against the new rules, new ones are checked against the platform's.
- "Save name settings" stays on the profile and says "Saved" — instead of going
  to Home, which read as an error.
- Deleting a local copy wipes it only if the profile really is local.

### Changed
- Default display name for a new profile: "Stauri User" → "New stauri user".

## [0.5.1] — 2026-11-22

### Added
- English documentation became the primary one: complete translations of every
  document in `docs/en/` (architecture, Web3 IM, comparison, auth and sync,
  networks and balances, providers and dApps, the ACC scheme, tests), and the
  links in `README.md` point to the English versions.
- The "About Stauri" screen: every section carries several links — to the
  internal document and to an external source (Status, Waku, Logos, ENS).
  External links open in the system browser, internal ones in an app window.

### Changed
- The `about.md` files in all four languages were rewritten: eight short sections
  with no technical detail — Web3 IM, the Status network, password and seed
  phrase, Stauri vs Status, the status-go patch, ENS, device sync, TODO/DONE.
- Creating a profile from an already open session logs out first: otherwise
  `waitForLogin` fires on a stale flag and the next login runs under the previous
  profile (`failed to open database`).
- On the name creation screen the field takes focus with its value selected — one
  Backspace clears it whole.

### Fixed
- A wrongly entered PIN is cleared after a refusal: the next taps begin a new
  entry instead of appending to what was already there.
- While a profile is being created the PIN pad shows a busy indicator instead of
  empty space: hashing the password and starting the node take seconds.

## [0.5.0] — 2026-11-21

### Added
- Syncing over the local network: two devices find each other automatically, six
  digits on both screens confirm it is the same connection, and the transfer goes
  over an encrypted channel. A USB cable is the fallback when Wi-Fi is
  unavailable.
- Profile on the login screen: a list of profiles with display names, and a
  choice to go to the creation wizard (PIN → seed phrase → name; everything but
  the PIN can be skipped).
- Separate Android builds: release (Stauri, mainnet) and dev (Stauri.dev, Sepolia,
  its own package id) install side by side; `reset-test-clients.sh SA` clears only
  dev, and the release profile with real funds and ENS is out of the script's
  reach.

### Changed
- PIN: 5–12 digits on the phone, trivial sequences rejected; 8–64 characters of
  four classes on the desktop. The strength check runs at creation only, and any
  saved PIN can still be opened.
- On the desktop the app locks when minimised to the tray, not when switching
  between windows.
- Syncing is now two-step: the profile is transferred only after Sync is pressed
  on both devices.

### Fixed
- The profile name in the list now updates after a change.
- Pairing errors carry the real reason instead of a generic "pairing failed".

## [0.4.1] — 2026-11-15

### Changed
- Strict password rules when creating a profile and when signing in: at least 8
  characters, upper- and lowercase Latin letters, a digit and a symbol. A
  confirmation field at creation. Profiles with a weaker password stop opening —
  this is a deliberate requirement, not a regression.
- Comments in the sources were translated into English and brought to a standard
  form (`docs/COMMENT_STYLE.md`): modules and functions documented by the rules of
  Rust, TypeScript and shell.

### Added
- A clean environment for checking a release: `scripts/clean-env.sh` and the
  `STAURI_DATA_DIR` / `STAURI_CONFIG_DIR` variables start a build with a separate
  profile without touching the working one.

## [0.4.0] — 2026-11-15

A stable release. The code matches `0.4.0-beta` (tag `v0.4.0-beta`); only the
version differs. The release exists to test auto-update: an installed beta should
receive 0.4.0 through `releases/latest`, which does not serve prereleases.
