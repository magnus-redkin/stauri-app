# Подключение dApp-плагина к Stauri

> Черновик, 2026-11-28. Реализации в Stauri ещё нет; процесс описан по итогам спайка на Android и первого плагина — [stauri-market-dapp](https://github.com/magnus-redkin/stauri-dapps).

Дополняет `dapp-plugin.md`: там — требования и модель угроз, здесь — конкретный процесс подключения и контракт рантайма. Рантайм выбран — **Extism** (поверх wasmtime). Разделы 3–5 старого документа (собственный ABI) заменены разделом «Контракт» ниже.

## 1. Из чего состоит dApp

| Часть | Что это | Кто исполняет |
|---|---|---|
| Модуль | `*.wasm`, ядро WebAssembly, собран из Rust/Go/Nim/C/… | Stauri в песочнице Extism |
| UI (необязательно) | статический бандл: `index.html` + JS/CSS любого фреймворка | Stauri в изолированном webview |
| Манифест | версия, хэш, права, адрес модуля, подпись издателя | Stauri проверяет и показывает |

Подключённым считается только dApp с манифестом и WASM-модулем. Обычное приложение (Rust, Tauri, что угодно) запускается как внешняя программа: отдельное окно, без API Stauri.

## 2. Процесс подключения

1. **Имя.** Пользователь вводит имя (`market`, `notes.example.eth`). v1: HTTPS-реестр или адрес GitHub Release; v2: ENS text record `stauri.manifest` с URL манифеста и его хэшем.
2. **Манифест.** Stauri скачивает манифест и проверяет подпись издателя (ed25519 над каноническим JSON манифеста).
3. **Показ.** Пользователь видит: имя и издателя (отпечаток ключа), версию, права, хэш модуля, размер. Установка — явное действие.
4. **Загрузка модуля.** HTTPS; SHA-256 модуля сверяется с манифестом до записи на диск — совпадает с полем `wasm[].hash`, которое проверяет и сам Extism.
5. **Проверка контракта.** Stauri читает экспорты модуля `wasmparser`-ом и сверяет с `stauri.exports` манифеста (`market_list`). Исходники не читаются.
6. **Установка.** Атомарно в каталог данных: `dapps/<id>/<version>/{module.wasm,ui/,manifest.json}`. Старые версии сохраняются для отката.
7. **Запуск.** Плагин создаётся при открытии его страницы: `PluginBuilder` с лимитами, WASI выключен, `allowed_hosts` пуст. Экземпляр живёт, пока открыта страница dApp.
8. **UI.** Бандл отдаётся из каталога dApp в отдельном webview (свой origin, без доступа к Tauri IPC и DOM Stauri); он обращается к хосту только через мост `postMessage` с белым списком.

Обновление: тот же путь; новые права требуют повторного согласия, смена ключа издателя — отдельного подтверждения. Удаление — код и, по выбору, данные `store.*`.

## 3. Контракт модуля

- Формат: ядро WebAssembly (`wasm32`), собранное с PDK Extism или вручную.
- Хостовые функции объявляются в namespace `extism:host/user`; у Market — ровно одна, `http_get_json(url) -> string`.
- Экспорты: функции с `#[plugin_fn]` (у Market — `market_list`), вход и выход — байты, обычно JSON.
- Запрещено и отклоняется при установке: неизвестные экспорты сверх манифеста, размер выше лимита, хэш не совпадает, модуль не грузится в тестовом инстансе с лимитами.
- Лимиты: `memory.max_pages` (у Market — 256, 16 MiB), fuel на вызов (10⁷ у dev-хоста), таймаут вызова с `CancelHandle`, один вызов за раз.

## 4. Хостовые функции

Права берутся из `stauri.permissions` манифеста и показываются пользователю при установке.

| Функция | Право | Подтверждение | Что доступно |
|---|---|---|---|
| `http_get_json(url)` | `http:<host>` | нет | только адреса с перечисленных хостов; ответ — текст, кэш и UA — на стороне Stauri |
| `log(msg)` | — | нет | журнал Stauri с меткой dApp |
| `store.get/set/delete` | `storage` | нет | собственное KV, квота |
| `message.send` | `messages` | всегда | отправка от имени пользователя |
| `wallet.address` | `wallet` | нет | адрес своего субаккаунта |

В v1 реализуется и проверяется на Market только `http_get_json`; остальное — по мере надобности. Сети напрямую у плагина нет: `allowed_hosts` остаётся пустым, все запросы идут через хостовую функцию, где живут прокси, User-Agent, кэш и лимиты.

## 5. UI-бандл

- Собирается любым фреймворком в статические файлы (`index.html`, JS, CSS); у Market — Svelte 5 + Vite.
- Загружается из каталога dApp, а не из сети; CSP запрещает внешние скрипты, шрифты и сеть; картинки — только с явно разрешённых хостов (монеты CoinGecko).
- Мост: `postMessage` с методами `call`, `getState`, `close`; результат — JSON. Никаких `invoke()`, `window.__TAURI__` и доступа к DOM Stauri.
- Тема: Stauri передаёт CSS-токены, чтобы плагин выглядел своим; у Market они повторены в `app.css`.

## 6. Разработка плагина

Репозиторий [stauri-market-dapp](https://github.com/magnus-redkin/stauri-dapps) — шаблон:

```
plugin/      Rust + extism-pdk: market_list() -> JSON
ui/          Svelte 5 + Vite: одна страница
dev-host/    тот же хост, что в Stauri: песочница, http_get_json, /api/market
manifest.json
scripts/build.sh
```

`cargo run --release -- --once` в `dev-host/` печатает ровно то, что Stauri получит от плагина; без флага — поднимает `http://127.0.0.1:8099` и отдаёт UI вместе с `/api/market`. Так плагин и интерфейс проверяются до появления в Stauri, а контракт совпадает с настоящим хостом.

Установочный хэш: `scripts/build.sh` собирает модуль и записывает SHA-256 в `manifest.json`; релиз v0.1.0 опубликован с этим артефактом, хэш в манифесте и в релизе совпадает.

## 7. Market как встроенный раздел

Раздел Market в Stauri остаётся, пока плагин `market` не установлен. После установки раздел рендерит UI-бандл плагина и получает данные из `market_list`; встроенный `fetch_market_data` и `MarketMain.svelte` можно будет удалить. Это первый пример замены встроенной страницы плагином: остальные встроенные разделы мигрируют по тому же шаблону.

## 8. Безопасность — что проверяется и что гарантируется

- Подпись манифеста + SHA-256 модуля: MITM и подмена файла закрыты.
- Песочница: без WASI, без сети, без файлов; только объявленные хостовые функции; fuel, память, время — лимитированы.
- UI: изолированный origin, CSP без сети, мост с белым списком.
- Деньги и сообщения: вне пределов плагина; позже — через хостовые функции с подтверждением.
- Журнал: установка, обновление, вызовы хостовых функций, остановки по лимиту.

Не гарантируется: полезность плагина, честность его UI в пределах его области, добросовестность издателя; и то, что ошибок нет в самом Stauri, webview или wasmtime.

## 9. Android

Спайк подтвердил: Extism 1.41 работает на `aarch64-linux-android` — хост собран NDK, плагин выполнен на устройстве и в shell, и в домене приложения (`run-as`). Требования: rustc ≥ 1.96 для extism 1.41 (в Stauri сейчас 1.94 — при интеграции поднять toolchain), NDK-линкер и `CC_aarch64_linux_android`. Издержки: размер (хост с wasmtime ≈ 26 МБ в релизе без стрипа; в приложении — с учётом линковки и strip), и Tier 3 Android у wasmtime — тестировать на устройстве в CI-смоуке.

## 10. Открытые вопросы

1. Формат подписи манифеста и канонизация JSON (одна реализация на Rust для хоста и для `scripts/`).
2. Реестр имён: HTTPS в v1, ENS в v2; кто хранит ключи издателей и как отзываются.
3. API моста UI ↔ хост: фиксированный минимум (`call`, `getState`) или наследование от `stauri.exports`.
4. Права `http:*`: список хостов на dApp; показывать ли пользователю конкретные адреса.
5. Жизненный цикл: одно окно/страница на dApp; фоновые вызовы — отложены.
6. Подпись модуля отдельно от манифеста (extism умеет `hash`, подпись — наша).

## 11. Что уже реализовано (0.5.6-dev)

- Раздел dApps: поле «Адрес манифеста dApp», установка, список установленных с версией, «Открыть» и «Удалить».
- Установка: манифест по HTTPS → проверка SHA-256 модуля и `ui.tar.gz` → распаковка с запретом абсолютных путей и `..` → атомарная запись в `dapps/<id>/<version>/`, указатель `current`.
- Запуск: Extism, WASI выключен, `allowed_hosts` пуст, лимит памяти из манифеста (по умолчанию 256 страниц), fuel на вызов, одна хоста-функция `http_get_json` с хостами из прав `http:<host>` и кэшем на 60 с.
- UI: отдаётся локальным сервером на 127.0.0.1 со случайным портом и токеном сессии в пути, CSP без сети; мост — `POST api/call` с `{function, input}`.
- Extism требует rustc 1.96: канал проекта закреплён `rust-toolchain.toml`.

Ещё не сделано: подпись манифеста ed25519, реестр имён и ENS, окна dApp на Android (сейчас только десктоп), подтверждения для будущих «опасных» хоста-функций.
