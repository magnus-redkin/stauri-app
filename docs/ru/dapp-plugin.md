# dApp-плагины Stauri: песочница и контракт бинарника

> Черновик для обсуждения, 2026-11-27. Реализации ещё нет; всё ниже — предложение, кроме раздела 0.
>
> Рантайм выбран — **Extism**; контракт модуля и процесс подключения описаны в `dapp-connect.md`. Разделы 3–5 ниже — исходные требования, их заменяет `dapp-connect.md`.

## 0. Принятые решения

1. Подключённый dApp выполняется **только в песочнице**. Нативные процессы с доступом к API Stauri не поддерживаются: обещать безопасность для произвольного бинарника с правами пользователя нельзя.
2. Материнский Svelte **не переиспользуется**. Плагин либо описывает интерфейс декларативно, либо приносит свой статический UI-бандл; Stauri его только показывает в изоляции.
3. Язык и фреймворк dApp — любые. Stauri проверяет **только контракт модуля** (структуру WASM-бинарника), исходники не читает и не ревьюит.
4. Обычное нативное приложение, в том числе на Tauri, можно запустить как внешнее: отдельное окно, никакого API Stauri. Это не «подключённый dApp», а просто программа.
5. Всё, что dApp делает с сообщениями и деньгами, идёт через брокер возможностей Stauri с подтверждением пользователя. Ключи, seed и PIN плагину не доступны никогда.

Следствие из п. 1 и 4: «подключённый dApp» — это WASM-модуль плюс, при желании, веб-UI. Нативная программа не может быть подключена, даже если очень хочет: у неё нет песочницы, а значит нет и гарантий.

## 1. Из чего состоит dApp

Пакет (то, что скачивается и устанавливается):

```
manifest.json      описание, права, хэши, подпись издателя
module.wasm        логика; контракт описан в §3
ui/                необязательно: статические HTML/JS/CSS
```

Манифест содержит: id, имя, версию, ключ издателя, URL и SHA-256 модуля, список прав, версию ABI, минимальную версию Stauri, при наличии — файлы UI и их хэши. Имя — это ярлык; настоящая идентичность — ключ издателя.

**Почему не «нативный бинарник в ОС-песочнице».** Можно было бы запускать обычный исполняемый файл в bwrap/AppContainer/seatbelt, но гарантии получаются разными на трёх платформах, а сеть и файловую систему всё равно приходится закрывать отдельно и неполно; Tauri-приложению с собственным webview и сетевым доступом это почти невозможно. WASM даёт одинаковую и проверяемую границу на всех платформах, поэтому v1 — WASM; нативная песочница остаётся возможным будущим режимом, но с честно другим уровнем гарантий.

## 2. Установка и реестр

Поток: пользователь вводит имя → Stauri получает манифест → показывает издателя, версию, права и хэш → скачивает и проверяет → валидирует контракт модуля → устанавливает → строка появляется в списке.

- **Источник имён, v1:** HTTPS-реестр (или GitHub Releases) по имени. **v2:** ENS text record `stauri.manifest` — имя `notes.stauri.eth` указывает на URL манифеста и его хэш. ENS здесь удобен, потому что уже есть в Stauri и принят в сообществе Logos, но он не является границей безопасности: доверие держится на подписи издателя.
- **Подпись:** ed25519 отдельным файлом или полем манифеста. Stauri показывает отпечаток ключа; при смене ключа у того же имени — отдельное явное предупреждение и подтверждение (TOFU).
- **Целостность:** SHA-256 модуля и UI-файлов из подписанного манифеста; загрузка только по HTTPS; установка атомарная, версии лежат раздельно (`dapps/<id>/<version>/`), возможен откат.
- **Обновления:** по умолчанию вручную. Автообновление допустимо, только если набор прав не изменился; любое новое право требует повторного согласия. Понижение версии — только явным действием пользователя.
- **Удаление:** удаляет код и, по выбору, данные dApp (`store.*`).

## 3. Контракт бинарника

Это единственное, что Stauri проверяет у dApp.

**Формат:** ядро WebAssembly, `wasm32`. Одна линейная память с объявленным максимумом (предлагается 64 MiB). Запрещены: разделяемая память, потоки, любые WASI-импорты, любые импорты кроме одного хостового вызова.

**Импорты:** ровно один — `stauri.host_call(ptr: i32, len: i32) -> i64` (упакованные `ptr << 32 | len` для ответа хоста).

**Экспорты:**

| Функция | Сигнатура | Назначение |
|---|---|---|
| `stauri_abi_version` | `() -> i32` | версия ABI, сейчас 1 |
| `stauri_alloc` | `(i32) -> i32` | выделить буфер под данные хоста |
| `stauri_free` | `(i32, i32) -> ()` | освободить буфер |
| `stauri_call` | `(i32, i32) -> i64` | обработать запрос, вернуть ответ |
| `stauri_event` | `(i32, i32) -> i32` | принять событие от хоста |

Данные — UTF-8 JSON. Запрос: `{"id","method","params"}`. Ответ: `{"id","result"}` или `{"id","error":{"code","message"}}`. Событие: `{"event","data"}`. Всё копируется через память модуля; указатели хоста плагину не передаются.

**Что проверяет валидатор Stauri:** магию и версию wasm; ровно один разрешённый импорт с точной сигнатурой; обязательные экспорты с точными сигнатурами (лишние экспорты разрешены — они не дают доступа); одну память без `shared` и в пределах лимита; отсутствие запрещённых секций; размер файла; совпадение SHA-256 с манифестом. Ничего другого: ни стиля, ни зависимостей, ни исходников.

**Лимиты:** топливо/инструкции на вызов, стена времени 100 мс на вызов, 64 MiB памяти, 1 MiB ответа, один вызов за раз, ограниченная очередь событий. Нарушение — вызов отклоняется, при повторных нарушениях dApp останавливается.

**Версии:** ABI версионируется; модуль с неизвестной ABI отклоняется установщиком с понятной ошибкой. `hello` возвращает версии хоста и модуля и список выданных прав.

## 4. Хост-API (возможности)

| Метод | Право в манифесте | Подтверждение | Что доступно dApp |
|---|---|---|---|
| `hello` | — | нет | версии, id, список прав |
| `log` | — | нет | журнал Stauri с меткой dApp, с ограничением частоты |
| `store.get/set/delete` | `storage` | нет | собственное KV-хранилище, квота 1 MiB |
| `time.now` | — | нет | текущее время, мс |
| `wallet.address` | `wallet` | нет | адрес своего субаккаунта |
| `wallet.balance` | `wallet` | нет | баланс **только** своего субаккаунта |
| `wallet.transfer` | `wallet.spend` | всегда | перевод; лимиты на операцию и сутки, опциональный allowlist |
| `message.send` | `messages` | всегда | отправка сообщения от имени пользователя |
| `events` (host → guest) | `messages` / `wallet` | при установке | `message.received`, `payment.received`, `network.changed`, `lifecycle.suspend/resume` |

Чего в API нет и не будет в v1: чтения списка контактов, чтения чужих чатов, доступа к основному балансу и адресу, произвольной подписи, RPC к сети, файловой системы, сети, системного времени сверх `time.now`, случайности сверх хостовой.

Вызов метода без соответствующего права — ошибка. Журнал фиксирует метод, dApp и результат; текст сообщений в журнал не пишется.

## 5. Кошелёк и сообщения

**Кошелёк.** Предлагается отдельный производный субаккаунт на каждый dApp (детерминированный путь от seed профиля, ключ хранит Stauri). Плагин получает адрес и баланс своего субаккаунта, но не ключ. Получение средств — это просто адрес и событие `payment.received`. Перевод всегда показывает пользователю сумму, получателя и имя dApp; подтверждение обязательно; лимиты и allowlist ограничивают ущерб от ошибки или взлома. Основной счёт недоступен.

**Сообщения.** Отправка — от имени пользователя, с подтверждением и показом точного текста и получателя; плагин не может подменить то, что видит пользователь. Приём в v1 — только в «своём» треде dApp (открытый вопрос §11): плагин не читает переписку пользователя и не получает список контактов.

## 6. Интерфейс

Материнский Svelte не используется — это прямое решение. Есть два режима, оба безопасны:

1. **Декларативный UI.** Манифест содержит схему экранов (текст, список, форма, кнопки, QR, статус), Stauri рендерит её своими компонентами и токенами темы. Кода плагина в интерфейсе нет вообще; выглядит нативно; для Notes этого достаточно.
2. **Свой статический бандл.** `ui/` — обычные HTML/JS/CSS, собранные любым фреймворком (Svelte, React, Vue, что угодно). Stauri показывает их в отдельном webview/iframe: собственный origin, `sandbox="allow-scripts"` без `allow-same-origin`, CSP запрещает сеть, шрифты и внешние скрипты; мост только через `postMessage` с белым списком методов; API Tauri и доступ к DOM Stauri отсутствуют. Данные — только через тот же хост-API.

Плагин не получает больше прав через UI, чем через WASM: мост вызывает те же методы с теми же правами и подтверждениями. Общий CSS-набор токенов можно выдать, чтобы интерфейс не выбивался из темы.

## 7. Безопасность

| Угроза | Мера |
|---|---|
| MITM при скачивании | HTTPS + SHA-256 из подписанного манифеста + подпись ed25519 |
| Подмена издателя | идентичность = ключ; смена ключа — явное подтверждение, отпечаток виден |
| Вредоносный модуль | WASM-песочница без WASI и сети, только хост-API, лимиты топлива/памяти/времени |
| Confused deputy | права из манифеста, подтверждение на деньги и сообщения, лимиты, allowlist, журнал |
| Фишинг в UI | изолированный origin, dApp не может рисовать вне своей области, бейдж dApp, запрет сети |
| Повтор/подмена вызовов | id запроса, один вызов за раз, никаких долгоживущих токенов |
| DoS | лимиты на вызов, частоту, размер ответа; остановка при нарушениях |
| Утечка данных | нет ФС и сети; UI без сети; только объявленные методы |
| Атака на обновление | подпись и хэш, запрет понижения без согласия, новые права — повторное согласие |
| Имперсонация имени | имя — ярлык; рядом всегда издатель и отпечаток |

**Честные ограничения.** Песочница защищает от кода dApp, но не от ошибок самого Stauri, webview и Wasmtime; тайминговые каналы полностью не закрываются; память WASM не гарантирует зануления; UI может заниматься социальной инженерией в пределах своей области. Всё это записывается в модель угроз, а не замалчивается.

## 8. Что гарантируется

- dApp не получает ключи, seed, PIN и не может подписать что-либо без Stauri.
- dApp не читает файлы, чужие чаты, контакты и основной счёт.
- Без подтверждения пользователя не уходит ни перевод, ни сообщение.
- Код dApp не исполняется в контексте Stauri и не имеет сети.
- Установка и обновление привязаны к подписи издателя и хэшу.

Чего гарантия нет: что dApp полезен, что его UI не пытается обмануть, что издатель не потеряет ключ. Это задача репутации, реестра и предупреждений.

## 9. Пример: Notes

Минимальный вертикальный срез, проверяющий всё сразу.

- Пакет: `manifest.json`, `notes.wasm`, декларативный UI.
- Права: `storage`, `messages` (только отправка), `wallet` (адрес и приём).
- Методы: `note.list`, `note.add`, `note.delete` — в своём KV; `note.share` — `message.send` с подтверждением; `tip.address` — адрес субаккаунта для «чаевых».
- Что демонстрирует: страницу подключения, проверку контракта, песочницу, квоту хранилища, подтверждение отправки и адрес для приёма.
- Порядок: сначала Rust (быстрее всего отладить контракт), затем Nim — тот же ABI, тонкий C-shim, доказательство языконейтральности. Обойтись без Rust можно, но первая итерация на нём дешевле: отлаживается один новый слой, а не два.
- ENS-регистратор как пример откладывается: покупка `.eth` сейчас заблокирована состоянием регистратора, а Notes проверяет те же способности.

## 10. Этапы и оценка

Один опытный разработчик, full-time, без учёта полировки:

| Этап | Недели |
|---|---|
| Спецификация ABI, манифеста и модели угроз | 1–2 |
| WASM-рантайм, валидатор контракта, лимиты | 3–4 |
| Установка, реестр, подписи, версии, обновления | 3–4 |
| Хост-API, субаккаунт, сообщения, подтверждения, журнал | 4–6 |
| Декларативный UI (для Notes) | 2–3 |
| UI-бандл в изоляции (второй режим) | 2–3 |
| Rust SDK + Notes | 1–2 |
| Nim SDK + Notes | 2–3 |
| Шаблоны, документация, демо | 1–2 |
| Ужесточение: фаззинг валидатора, лимиты, ревизия | 3–4 |

MVP (Rust Notes, декларативный UI, установка по HTTPS с подписью): **10–14 недель**. Полный вариант с Nim, UI-бандлом и ужесточением: **5–7 месяцев**. Самый дорогой риск — не протокол, а реестр доверия и качество валидатора.

## 11. Открытые вопросы

1. **Субаккаунт dApp:** делать его средством status-go или ключом внутри Stauri? Как он восстанавливается из seed и как показывается в кошельке?
2. **«Свой тред» для сообщений:** отдельный чат на dApp, тег в сообщениях или отдельный ключ? Что именно доставляется плагину и как это объясняется пользователю?
3. **Декларативный UI:** хватает ли фиксированного набора блоков; нужен ли режим «только bundle» уже в v1?
4. **Компонентная модель WASM (WIT)** вместо JSON-ABI: лучше типы и тулинг, но слабее поддержка Nim/Go; оставляем JSON в v1, WIT — кандидат в v2.
5. **Реестр:** ENS или HTTPS в v1; кто хранит ключи издателей и как отзываются скомпрометированные.
6. **Лимиты денег:** фиксированные или настраиваемые; как показывать пользователю дневной остаток.
7. **Хранилище:** квота, резервное копирование при переносе профиля, что делать при удалении dApp.
8. **Фоновая работа:** в v1 dApp живёт только пока открыт его экран — подтвердить, что этого достаточно.
9. **Проверка контракта:** набор тестов и фаззинг валидатора; считать ли его частью safety core с отдельным ревью.
