# Ужесточение механизма dApp-плагинов

> План, 2026-11-28. Исходные документы: `dapp-connect.md` (процесс и контракт), `dapp-plugin.md` (требования и модель угроз), `dapp-plugins.md` — по мере появления. Пример — [stauri-market-dapp](https://github.com/magnus-redkin/stauri-dapps).

## 1. Где мы сейчас

Работает и проверено на деле: установка из чужого репозитория по адресу манифеста, SHA-256 модуля и UI-архива, песочница Extism (WASI выключен, `allowed_hosts` пуст), одна хоста-функция `http_get_json` с allowlist по правам, UI-бандл на локальном сервере с токеном сессии и CSP без сети, мост `POST api/call`. Market открывается и показывает данные.

### Негативные прогоны (все проходят)

| Сценарий | Ожидание | Результат |
|---|---|---|
| Хэш модуля не совпадает с манифестом | отказ, ничего не установлено | ✓ `hash mismatch`, каталога нет |
| Хэш не указан | отказ | ✓ `hash is missing` |
| Манифест отдаёт 404 | отказ | ✓ `HTTP 404` |
| Модуль с совпадающим хэшем, но не wasm | отказ | ✓ `does not load in the sandbox` |
| Модуль импортирует неизвестную функцию | отказ при инстанцировании | ✓ не загружается |
| Модуль импортирует WASI | отказ при инстанцировании | ✓ не загружается |
| Плагин вызывает `http_get_json` без права | отказ хоста | ✓ `host not allowed` |
| Архив UI с `..` или абсолютным путём | отказ распаковки | ✓ проверка пути |
| `id`/версия с `..` или `/` | отказ | ✓ проверка алфавита |

### Чего ещё нет

- Подписи манифеста (ed25519) и отображения издателя.
- Проверки объявленных экспортов на стороне установки.
- Стенного таймаута вызова (есть fuel и лимит памяти).
- Обновлений и отката в интерфейсе, удаления старых версий.
- CSP, привязанного к правам плагина (сейчас картинки разрешены только с CoinGecko).
- Android-окна dApp, реестра имён и ENS.

## 2. Модель безопасности — подробно

### 2.1 Границы доверия

```
пользователь ── подтверждает установку ──► Stauri ── загружает ──► HTTPS-источник
                                             │                       (не доверяем)
                                             ├─ проверяет манифест и файлы
                                             ├─ запускает модуль в песочнице ──► плагин (не доверяем)
                                             └─ отдаёт UI на отдельном origin ──► бандл (не доверяем)
```

Stauri доверяет только себе: ключам, PIN, профилю. Всё, что приходит из сети (манифест, модуль, UI), считается враждебным до проверки. Плагин не доверяет Stauri и не может ему навредить; UI не доверяет плагину и получает только выданные данные.

### 2.2 Конвейер установки

1. **Адрес манифеста.** Только `https`; размер ответа ≤ 1 МиБ; редиректы обрабатывает `reqwest` (ограниченно), loopback-адреса не идут через системный прокси.
2. **Манифест.** JSON с обязательными `name`, `version`, `wasm[].url`, `wasm[].hash`, `stauri.id`, `stauri.exports`. Неизвестные поля игнорируются, отсутствие обязательных — отказ.
3. **Идентификаторы.** `id` и версия — только `[a-zA-Z0-9._-]`, длина ≤ 64, без `.`, `..`, `/`. Иначе отказ: иначе путь установки выйдет за каталог dApp.
4. **Модуль.** Скачивается по `https`, ≤ 32 МиБ, SHA-256 сверяется с манифестом; пустой хэш — отказ (иначе проверка стала бы необязательной).
5. **UI.** Архив `tar.gz` ≤ 64 МиБ, SHA-256 сверяется; распаковка запрещает абсолютные пути, `..` и drive-префиксы; число записей ≤ 5000.
6. **Инстанцирование.** Собранный модуль загружается в ту же песочницу, в которой будет работать. Модуль, который не загрузится, не устанавливается.
7. **Атомарность.** Всё пишется в `.staging`, затем каталог переименовывается, `current` обновляется последним. Неудачная установка не оставляет полусобранного dApp; старые версии сохраняются.

### 2.3 Рантайм-песочница

- **Движок:** Extism на wasmtime. Модуль — ядро WASM без WASI: нет файлов, часов, случайности, процессов.
- **Сеть:** недоступна и в самом рантайме (`allowed_hosts` пуст), и вне его — у плагина нет сокетов. Наружу только хостовые функции.
- **Память:** одна линейная память, лимит из манифеста (`max_pages`, по умолчанию 256 = 16 МиБ). Проверено: при 16 страницах реальный плагин падает с `oom`, то есть лимит применяется.
- **Вычисления:** fuel на вызов (10⁷); исчерпание — ошибка вызова, а не зависание процесса.
- **Состояние:** одна инстанция на dApp, создаётся при первом вызове, пересоздаётся после ошибки. В будущем — стенной таймаут с `CancelHandle`.
- **Импорты:** модуль может импортировать только объявленные хостовые функции; неизвестный импорт и WASI-импорт не дают модулю загрузиться (проверено).

### 2.4 Хостовые функции

Единственная в v1 — `http_get_json(url) -> string`:

- только `https`; хост из URL обязан совпадать с правом `http:<host>` или быть его поддоменом (`*.host`);
- GET и кэш ответа на 60 секунд; размер ответа ограничен манифестом (`max_http_response_bytes` пока не применяется — в плане);
- User-Agent `Stauri/<версия>`, системный прокси, как у остального приложения;
- ошибка — JSON с причиной, плагин её видит, пользователь — в журнале.

Принцип: всё, что плагин может увидеть снаружи, объявлено в `stauri.permissions` и показано при установке.

### 2.5 Изоляция UI

- UI отдаётся локальным сервером на `127.0.0.1` со случайным портом; в пути — токен сессии (32 байта), без него любой запрос получает 403.
- Страница живёт на собственном origin; CSP: `default-src 'self'`, `script-src 'self'`, `connect-src 'self'`, картинки — `'self'` плюс явный allowlist.
- Мост — `POST /s/<токен>/api/call` с `{function, input}`; ответ — строка от модуля. Никакого `invoke()`, `window.__TAURI__` и доступа к DOM Stauri: окно dApp не имеет прав Tauri.
- Будущее: методы моста расширяются только вместе с хостовыми функциями и только по правам.

### 2.6 Секреты и деньги

Ключи, seed, PIN, основной адрес и баланс недоступны плагину и его UI. Будущие `wallet.*` и `message.send` выполняет Stauri после явного подтверждения; плагин получает результат, а не полномочия. Субаккаунт dApp — отдельный производный ключ, ключ хранит Stauri.

### 2.7 Данные и жизненный цикл

`dapps/<id>/<version>/` + указатель `current`; старые версии остаются для отката; удаление убирает каталог целиком. Будущее хранилище плагина (`store.*`) — отдельный каталог с квотой, очищается при удалении по выбору.

### 2.8 Наблюдаемость

Сейчас пишутся установка и ошибки вызова. В плане — журнал установок/удалений, вызовов хостовых функций (функция, dApp, результат; без текста сообщений) и остановок по лимитам, с экраном в настройках.

### 2.9 Остаточные риски

- Манифест приходит по HTTPS с хэшем внутри себя: компрометация хостинга подменяет и файл, и хэш. Закрывается подписью издателя.
- Любой процесс пользователя может попытаться угадать токен сессии; 32 байта делают это невыполнимым, но сервер всё равно слушает loopback.
- Ошибки в wasmtime, webview и самом Stauri.
- Социальная инженерия в пределах области UI плагина.

## 3. План доработки

Порядок — по возрастанию ценности для безопасности.

### P0. Замкнуть установку и запуск (2–3 недели)

1. **Подпись манифеста ed25519.** Канонический JSON (JCS или сортировка ключей), поле `signature`, отдельный ключ издателя (`publisher`), проверка перед установкой; отображение отпечатка; TOFU на смену ключа; отказ при подписи без доверия.
2. **Проверка экспортов.** `wasmparser` до инстанцирования: набор и сигнатуры экспортов совпадают с `stauri.exports`; лишние экспорты допустимы, отсутствующие — отказ.
3. **Стенной таймаут.** `CancelHandle` + лимит (например, 500 мс) на каждый вызов; UI получает `timeout`, инстанция пересоздаётся.
4. **Лимит ответа хоста.** Применять `max_http_response_bytes`.
5. **Обновления и откат.** Кнопка «Обновить» и список версий с откатом; запрет молчаливого понижения; diff прав при обновлении.
6. **Удаление и чистка.** «Удалить» убирает все версии; кнопка «удалить старые версии».

**Критерий готовности:** установка без подписи отклоняется; подмена хэша в подписанном манифесте ломает подпись; тесты на всё перечисленное; журнал установок виден.

### P1. Идентичность и реестр (2–3 недели)

- Реестр имён (файл в репозитории + GitHub Releases) и ENS text record `stauri.manifest` как источник адреса манифеста.
- Экран установки: издатель, отпечаток, права, хэш, кнопка «Доверять».
- Отзыв ключа и списки отозванных.

### P2. Возможности для dApp (3–4 недели)

- `store.*` с квотой, `message.send` с подтверждением, `wallet.address`/`wallet.transfer` с субаккаунтом и лимитами.
- Журнал вызовов и экран разрешений; отзыв прав без удаления.
- События `message.received`, `payment.received`.

### P3. Платформы и упаковка (2 недели)

- Android: страница dApp внутри приложения (вместо окна) или окно, если платформа позволит; смоук-тест на устройстве.
- Размер: замер релиза с extism, обрезка wasmtime (features), цель — не больше +15 МиБ.
- CI: сборка плагина-примера и установка в тестовом каталоге.

### P4. Примеры на других языках (3–4 недели, после P0–P1)

- **Notes на Nim.** Nim → wasm32 + C-шим к `extism:host/user`; экспорт `note_list/note_add/note_delete`; права `storage`, `messages`; UI — декларативный или свой бандл. Доказывает языконейтральность и простоту подключения.
- **ENS-регистрация на Go.** `go-pdk`, вызовы через новые хостовые функции (`wallet`/`tx` только после P2), проверка регистрации `.stateofus.eth` и `.eth`; покупка `.eth` откладывается состоянием регистратора.
- Шаблоны репозиториев и раздел в документации «свой dApp за вечер».

## 4. Расширение тестов безопасности

Добавить к текущим 12:

- подпись: неверная, чужая, отсутствующая, изменённый манифест после подписи;
- downgrade: установка более старой версии при включённой защите;
- огромные файлы и tar.gz-бомба (лимиты по числу записей и распакованному размеру);
- вызов с `http://` и с хостом-поддоменом (`evil.example.com` против права `example.com`);
- плагин, который крутится вечно (fuel и таймаут);
- UI, пытающийся `fetch` на чужой origin (CSP);
- UI, пытающийся выполнить inline-скрипт (CSP);
- параллельные вызовы одного dApp и пересоздание инстанции после ошибки.

## 5. Оценка

P0 — 2–3 недели, P1 — 2–3, P2 — 3–4, P3 — 2, P4 — 3–4. Итого до «безопасного механизма установки» (P0+P1) — около месяца одного разработчика; до dApp с деньгами и сообщениями — ещё два; примеры на Nim и Go — после этого.

## 6. Открытые вопросы

1. Канонизация JSON для подписи: JCS целиком или собственный детерминированный порядок.
2. Где живёт реестр: файл в `stauri-app` или отдельный репозиторий с CI-подписью.
3. Стенной таймаут: 200, 500 мс или настраиваемый — и что видит UI при превышении.
4. Отзыв ключа: список в реестре или событие в ENS.
5. Android: отдельное окно или встроенная страница dApp.
